      Part A · Build the library

      Runs once, offline. Turns the raw book into 2,296 searchable passages stored in a vector database.

      01

      src/ingest.py · scripts/verify_source.py

      The raw source file

      The book arrives as one plain-text file from Source Library: a transcription of A. C. Kaviratna's English translation (Calcutta, 1890 onward). It opens with a download header, then every scanned page begins with a [Page N] marker. The header is thrown away, and the file is fingerprinted to prove it is the exact copy the project was built on.

      Formula · source fingerprint
      start = position of “[Page 1]”
      fingerprint = SHA-256( normalise_line_endings( file[start :] ) )

      = c25eb5c353a774ebf4e02fb88d412e923e3354e2c8627305bbbc6be14cead23a

      valid ⇔ pages = 1988 ∧ fingerprint = expected

      Two downloads of the same book differ only in the header, so hashing from [Page 1] gives the same fingerprint every time, on Windows or Linux line endings.

      src/ingest.py · split_pages(), parse_page(), clean_text()

      Page by page: read, clean, separate footnotes

      The file is cut at every [Page N] marker. On each page the transcriber's tags (scan quality, page type, running header…) are read as data and removed; markdown marks are stripped; and the translator's footnotes are moved out of the main text, so they can never be mistaken for Charaka's words.

      Rules · quality flags
      empty ⇔ type = text ∧ |main_text| < 50 chars
      garbled ⇔ lettersvisible characters < 0.6
      • Footnote split: the first --- line that is not followed by a heading starts the footnotes; otherwise the first line starting with a footnote mark (*, †).
      • Other flags: poor scan quality, words marked unclear, missing printed page number.

      src/chunk.py · lesson_paragraphs(), pack()

      Chunking: cutting lessons into passages

      Lessons are far too long to search as a whole (up to 19,700 words), and pages break sentences in half. So each lesson is read as one continuous text and packed, whole paragraph by whole paragraph, into passages (“chunks”) that the embedding model can read completely: at most 512 tokens, including a context line naming the lesson.

      Formula · chunk size limit
      size = tokens(context) + Σ tokens(paragraph) + 2 ≤ 512
      = 21 + (83+31+295+40+32) + 2 = 504 ✓

      The 2 is the model's [CLS] and [SEP] tokens. Sizes are counted in the model's own tokens, not words, because Sanskrit words split into many pieces:

      • A sentence or hyphenated word cut by a page break is joined back.
      • A short last paragraph (≤ 100 tokens) is repeated at the start of the next chunk (overlap).
      • Translator's footnotes become separate chunks of kind note.

      05

      src/embedder.py · src/index.py

      Embedding: turning a passage into 384 numbers

      Each chunk (context line + passage) goes through the embedding model BAAI/bge-small-en-v1.5, run locally with fastembed (ONNX, no API key). The model reads the tokens and outputs one vector: 384 numbers that place the passage's meaning in space. Passages about similar things end up close together.

      Formula · the vector
      h = model( tokens )[CLS] ∈ ℝ384
      v = h‖h‖ ,  ‖v‖ = √(Σ vi²) = 1.0000

      Normalising every vector to length 1 makes the similarity in step 08 a simple dot product.

      Embedding all 2,296 chunks takes about 7 minutes on a laptop CPU and is done once.

      06

      src/index.py · save_index() · docker-compose.yml

      Storing the vectors in Qdrant

      Every chunk becomes one point in the Qdrant collection charaka_chunks: an id, its vector, and a payload with all its details. Qdrant runs as a server in Docker (port 6333), so the API, the chat and the evaluation scripts can use it at the same time.

      Collection settings
      vectors: size 384, distance Cosine
      metadata: model, chunks_sha256

      chunks_sha256 = 250f9469e76f2708342aed6f1eb777e2bf706375c9419a6357fd3f80a7c2c853

      Safety check: when the chatbot opens the collection it recomputes the fingerprint of the current chunks. If they changed and nobody re-indexed, it refuses to start instead of returning the wrong passages.

      The payload lets Qdrant filter inside the database, e.g. kind = "text" for Charaka's text only.

      src/embedder.py · embed_query()

      Embedding the question

      The question goes through the same model, so it lands in the same 384-number space as the passages. BGE models search better when a short question carries an instruction, so it is added in front (passages are embedded without it).

      Formula
      q = normalise( model( instruction + question )[CLS] )

      The question is also sent, as plain words, to keyword search (step 09). Both searches run on every question.

      08

      src/retrieve.py · Qdrant query_points()

      Meaning search: cosine similarity in Qdrant

      Qdrant compares the question vector with all 2,296 passage vectors and returns the 50 most similar. This finds passages by meaning, even when they use different words from the question.

      Formula · cosine similarity
      cos(q, d) = q · d‖q‖ ‖d‖ = Σi=1..384 qi di

      Both vectors have length 1, so the denominator is 1. Example: the passage that says “Of bones there are three hundred and sixty” scores 0.7961, rank 1.

      6 of the top 8 come from Sharira Sthana Lesson VII, the lesson that counts the parts of the body.

      09

      src/bm25.py · BM25.scores()

      Keyword search: BM25 word matching

      In parallel, the question is matched word by word with BM25, the classic search-engine formula. It catches exact Sanskrit terms (“Rasayana”, “pitta”) that the English embedding model barely knows. Spelling is normalised first, so the translator's “Çarira” matches a reader's “Sharira”.

      Formula · BM25
      score(D,Q) = Σt∈Q IDF(t) · f(t,D) · (k₁+1)f(t,D) + k₁·(1 − b + b·|D|/avgdl)
      IDF(t) = ln( 1 + N − n(t) + 0.5n(t) + 0.5 )
      • f(t,D): times word t appears in passage D
      • n(t): passages containing t; N = 2,296
      • |D|: passage length; avgdl = 155.2 words
      • k₁ = 1.5: repeats stop counting quickly; b = 0.75: long passages are penalised

      Rare words (“bones”, IDF 3.12) count far more than common ones (“body”, IDF 0.95).

      10

      src/retrieve.py · Retriever.search()

      Fusion: Reciprocal Rank Fusion ranks the chunks

      The two rankings are merged. Cosine scores (0 to 1) and BM25 scores (0 to 12+) are on different scales, so the fusion uses ranks, not scores. A passage ranked well by both methods rises to the top. The best 6 go to the language model.

      Formula · RRF
      RRF(d) = Σmethod 1k + rankmethod(d) ,  k = 60
      S1 = 160+1 + 160+9 = 0.01639 + 0.01449 = 0.03089

      The BM25 winner (about how bones arise from flesh) is only rank 22 by meaning, so it lands second. The correct passage wins because both methods find it.

      Each ranking goes 50 deep; a passage missing from one list gets nothing from it.

        src/llm.py · LLM.complete()

        The language model writes an answer

        The prompt goes to openai/gpt-oss-20b through NVIDIA's OpenAI-compatible API (the key stays on the server). gpt-oss is a reasoning model: it thinks first, and its reasoning comes back separately and is discarded. Only the answer text is used.

        Formula · sampling with temperature
        P(tokeni) = ezi / TΣj ezj / T ,  T = 1.0

        The model picks each next token from this distribution. At low temperatures this small model fell into loops (“Kaphaja Kaphaja…”) until it ran out of tokens, so T = 1.0 is used, as its makers recommend. Faithfulness comes from the rules and the code checks, not from temperature.

        • Up to 4,096 output tokens; an empty reply is retried once.
        • Network, key and rate-limit errors become clear messages.

        src/api.py · frontend/ (React)

        The response the user sees

        The API returns the checked answer, only the sources it actually cites, the warnings and the disclaimer. The React app turns each citation into a chip that opens the passage, badged by whose words it is.

        What the checks cannot catch. The number is right (360, as in S1), but the model also wrote “twenty-seven pieces of bone in each of the sections”, which is not in the passage. The checks prove that every citation points to a real passage; they cannot prove every sentence is supported. That is why the sources are always shown, so a reader can verify the answer against the text in one click.

        Formulas · metrics
        hit@k = questions with a correct passage in top kall questions
        MRR = 1|Q| Σq∈Q 1rank of first correct passage

        Hybrid beats either method alone: meaning only scores 92% hit@5 (MRR 0.84), keywords only 85% (MRR 0.74). Questions in everyday words are the weak spot (70% hit@5), because the 1890s translation uses different vocabulary.
